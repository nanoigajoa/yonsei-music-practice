# 음대 연습실

연세대학교 음악대학 연습실의 공실 확인, 모바일 예약·취소·반납, 이용 알림과 익명 라운지를 제공하는 PWA입니다. 휴대폰에서 방을 예약하고, 현장에서는 실물 학생증을 태그해 이용합니다.

[웹앱 열기](https://app-roan-beta-51.vercel.app) · [운영자 문의](https://open.kakao.com/o/suKUBswi)

홈의 오른쪽 메뉴에서 찜한 방 관리, 알림 설정, 공지사항, 운영자 문의, 시설신문고, 라운지 등을 엽니다. 음대 라운지는 홈 시계 아래에서도 바로 열 수 있습니다. 방 카드마다 찜 버튼을 배치하지 않고 별도 화면에서 설정합니다.

방 색상은 공실이 초록색, 인증대기가 노란색입니다. 사용 중인 방은 종료 20분 전부터 붉은색으로 표시하며, 색상 범례는 **두칸남음**입니다. 붉은색 표시는 즉시 예약 성공을 의미하지 않으며, 최종 가능 여부는 학교 서버가 확인합니다.

## 예약과 취소

1. Google 로그인 후 학번을 연결합니다. 학교 키오스크 로그인으로 이용 가능 여부를 확인하고, Google 계정과 학번을 일대일로 연결합니다.
2. 방과 시간을 선택하면 교내 게이트웨이가 학교 서버에 예약을 요청합니다. 학교 응답을 확인한 뒤 인증대기로 표시합니다.
3. 예약 시작부터 태그 마감까지 현장 단말기에 학생증을 태그합니다. 게이트웨이가 태그 완료를 확인해 사용 중으로 전환합니다.
4. 태그 전에는 **예약 취소**, 사용 중에는 **연습실 반납하기**를 이용합니다.

화면에서 야간이라는 이유로 방이나 예약 시간 선택지를 숨기지 않습니다. 실제 공실, 이용 자격과 시간 제한은 학교 서버의 응답을 따릅니다.

### 중복 요청과 취소 응답 처리

- 예약 요청 ID를 저장해 응답이 끊겨도 같은 요청의 결과를 복구합니다. 결과가 불확실한 예약을 새 요청으로 덮어쓰지 않습니다.
- SQLite 선점과 예약 ID별 잠금으로 중복 예약 및 태그·취소·반납 경합을 제어합니다.
- 미태그 취소에는 추가 태그가 필요하지 않습니다. 학교의 명시적 취소 성공을 확인한 뒤 화면과 DB를 정리합니다.
- 취소 실패나 연결 오류를 성공으로 표시하지 않습니다. 늦게 도착한 옛 취소 응답도 새 예약을 지우지 못하게 합니다.
- 취소는 원래 방과 예약번호의 취소 링크를, 반납은 학교의 현재 사용 예약번호를 확인합니다. 다른 예약을 찾아 대신 취소·반납하지 않습니다.

120분 예약의 학교 전송 형식은 마지막 분을 시작 시각의 **119분 뒤, 59초**로 표현하고, 앱의 논리적 종료 시각은 **시작 + 120분**으로 유지합니다. 학교가 이를 121분 요청으로 해석하지 않도록 하는 보정입니다.

## 매일 21:50 자동반납

> 매일 21:50에 이 앱으로 빌려 사용 중인 방을 자동 반납해요. 남은 시간과 관계없이 적용되니 완료 여부를 확인해 주세요.

- **대상:** 휴대폰에서 이 앱으로 예약하고, 21:50 시점에 서버에서 태그 완료가 확인된 이용 예약입니다. 예정 시작 시각을 기준으로 제외하지 않습니다.
- **제외:** 미태그 예약, 현장 키오스크에서 직접 빌린 방, 앱 예약인지 확인할 수 없는 과거 기록입니다. 키오스크 예약을 앱으로 불러와도 자동반납 대상이 되지 않습니다.
- **대상 확정:** 예약 ID와 학교 예약번호를 SQLite에 저장합니다. 대상이 없었던 날도 빈 목록을 저장합니다.
- **재시도:** 확정한 예약만 30초 간격으로 재시도하며, 22:00부터 새 반납 시도를 시작하지 않습니다. 재시작이나 이후 폴링에서 새 예약을 목록에 추가하지 않습니다.
- **완료 처리:** 학교의 성공 응답을 받은 예약만 반납 완료로 기록합니다. 자동반납 후 열린 홈 화면의 하단 예약 바도 서버 상태와 동기화합니다.

예를 들어 20:10~22:10 예약도 21:50에 사용 중이면 남은 시간과 관계없이 반납 대상입니다. 대상 확정 후 새로 빌린 방은 이전 예약의 재시도 때문에 반납되지 않습니다.

학교 연결이나 태그 상태 동기화가 늦으면 반납 대상 확인 또는 실행이 지연될 수 있습니다. 21:50 이후에야 태그 완료가 확인된 예약은 제외하며, 서버가 21:50~22:00 내내 중단된 경우 그날 자동반납을 실행하지 않습니다. 성공 응답을 확인할 수 없는 경우에는 완료를 추정하지 않으므로, 이용자는 실제 반납 여부를 확인해야 합니다.

새 공지는 앱을 열거나 다시 돌아올 때 **확인** 버튼이 있는 팝업으로 표시합니다. 확인 여부는 사용자·기기·공지 버전별로 저장하며, 같은 공지는 반복 표시하지 않습니다. 확인한 공지는 메뉴의 공지사항에서 다시 볼 수 있습니다. 자동반납 공지는 서버에서 해당 기능이 활성화된 경우에만 게시됩니다.

## 음대 라운지와 알림

라운지는 Google 로그인과 학번 연결을 완료한 이용자의 텍스트 채팅방입니다. 화면에는 모두 **익명**, 본인의 글은 **익명 (나)**로 표시합니다. 표시 이름이 익명인 것이며 서버에는 계정 UID가 저장됩니다.

- 메시지는 한 번에 500자까지 전송합니다. 사진·파일 전송은 지원하지 않습니다.
- 처음에는 최신 100개를 보여주고, 이전 대화를 50개씩 불러옵니다. 화면에 유지하는 대화는 최대 500개입니다.
- 서버는 최대 7일·최근 1,000개 범위의 대화를 보관합니다. 화면 표시 개수와 서버 보관 개수는 다릅니다.
- 입장 화면에서 라운지 이용 규칙을 확인할 수 있습니다.

찜한 방이 공실로 바뀐 것을 게이트웨이가 감지하면 FCM 알림을 발송합니다. 학교 현황 수집과 푸시 전달에 시간이 걸릴 수 있어 실제 반납 순간의 즉시 수신을 보장하지는 않습니다. 알림을 누르면 해당 방으로 이동합니다.

태그 마감은 5분·2분 이내, 이용 종료는 10분 이내에 알림을 생성합니다. 알림 설정에서 각각 켜거나 끌 수 있으며, 기기 권한과 테스트 알림으로 수신 여부를 확인할 수 있습니다.

## 데이터와 구조

```text
휴대폰 PWA — Next.js / Vercel
  ├─ Firebase Authentication: Google 로그인
  ├─ Firestore: 프로필 및 기존 기능의 데이터
  └─ 교내 FastAPI 게이트웨이 — Proxmox LXC / systemd
       ├─ 학교 키오스크: 현황 조회, 예약, 태그 확인, 취소, 반납
       ├─ SSE /stream: 방 현황 전송
       ├─ WebSocket /community/lounge/ws: 익명 라운지
       ├─ reservations.sqlite3: 예약·학번 연결·반납 대상·연습기록
       ├─ community.sqlite3: 대화·찜·기기 토큰·알림 설정 및 발송 기록
       └─ FCM: 공실·태그·이용 종료 알림
```

| 영역 | 사용 기술 |
| --- | --- |
| 웹앱 | Next.js 16 App Router, React, TypeScript, Tailwind CSS |
| 인증·푸시 | Firebase Authentication, Firebase Cloud Messaging |
| 프로필·기존 기록 | Cloud Firestore |
| 교내 API | Python, FastAPI, HTTPX, Beautiful Soup |
| 예약·커뮤니티 저장 | SQLite, 영속 파일 경로 |
| 실시간 전송 | 방 현황 SSE, 라운지 WebSocket |
| 운영 | 웹앱 Vercel, 교내 API Proxmox LXC + systemd + Tailscale 공개 연결 |

마이페이지의 새 연습기록은 예약 DB에서 자동으로 가져옵니다. 인증대기도 기록에 나타나지만 예정된 120분을 곧바로 실제 연습량으로 더하지 않습니다. 사용 상태와 실제 반납 시각으로 집계하고, 취소·미태그 만료는 연습량에 포함하지 않습니다. 과거 Firestore 기록은 별도로 유지합니다.

방 현황은 기본 20초 간격의 학교 조회와 예약·반납 후 갱신을 거쳐 메모리 상태에서 SSE로 전달합니다. 모든 방 현황 스냅샷을 영구 저장하는 구조는 아닙니다. 예약·반납 이력과 커뮤니티 데이터는 각각 SQLite에 저장합니다.

## 운영과 업데이트

현재 운영은 교내 네트워크에 접근 가능한 LXC의 `yonsei-practice-gateway.service`를 사용합니다. 저장소에 남아 있는 Fly.io 설정, Docker·Cloudflare 배포 자료와 Vercel 알림 크론은 현재 게이트웨이 운영 절차와 구분해서 확인해야 합니다.

현재 서버의 `update-community.py`가 설치된 디렉터리에서 다음 한 줄로 최신 기능 버전을 적용합니다. `curl`을 설치하거나 업데이트 스크립트를 다시 다운로드할 필요가 없습니다.

```bash
python3 update-community.py b70703b26dd416840139d695ce71e311c321476b
```

업데이트는 기존 DB와 환경 설정을 교체하지 않습니다. `"db": "unchanged"`는 DB 파일을 보존했다는 뜻이며, 새 기능에 필요한 열과 테이블은 서버 시작·DB 접근 시 추가될 수 있습니다. `RESERVATIONS_DB_PATH`와 `COMMUNITY_DB_PATH`가 가리키는 영속 파일을 함께 백업합니다.

```bash
systemctl status yonsei-practice-gateway.service --no-pager
journalctl -u yonsei-practice-gateway.service -f
```

`/health`의 `status: "ok"`와 함께 `booking_enabled`, `daily_return_enabled`, `daily_return_time: "21:50"`을 확인합니다. `data_ready: false`, `updated_at: null`은 아직 방 현황이 준비되지 않았다는 뜻입니다. 재시작 후에도 계속 유지되면 수집 로그와 학교 연결을 확인합니다.

| 환경 변수 | 용도 |
| --- | --- |
| `BOOKING_ENABLED` | 예약 기능 활성화; 기본 `false` |
| `ALLOWED_TEST_ROOMS` | 예약 허용 방 목록; 전체 허용은 `*` |
| `DAILY_RETURN_ENABLED` | 21:50 자동반납; 기본 `true`이며 `BOOKING_ENABLED=true`도 필요 |
| `AUTO_RETURN_ENABLED` | 기존 종료시각 기반 자동반납 옵션; 현재 운영은 `false`로 유지 |
| `POLL_INTERVAL_SECONDS` | 현황 수집 간격; 기본 20초, 최소 10초 |
| `RESERVATIONS_DB_PATH`, `COMMUNITY_DB_PATH` | 영속 SQLite 파일 경로 |
| `ALLOWED_ORIGINS` | 웹앱의 허용 출처 |
| `BOOKING_TOKEN_SECRET` | 예약 권한 토큰 서명 및 학번 연결용 HMAC 비밀키 |
| `GOOGLE_APPLICATION_CREDENTIALS` 또는 `FIREBASE_SERVICE_ACCOUNT_KEY` | 서버 Firebase 관리자 인증 |

서비스 계정과 비밀키는 서버 설정으로 관리하며 Git에 포함하지 않습니다.

## 개발과 검증

웹앱은 웹앱 브랜치의 `app/`에서 실행합니다. `app/.env.local`에 Firebase 웹 설정의 `NEXT_PUBLIC_FIREBASE_*`, 푸시용 `NEXT_PUBLIC_FIREBASE_VAPID_KEY`, 교내 게이트웨이 주소인 `NEXT_PUBLIC_KIOSK_API_URL`을 지정합니다. `NEXT_PUBLIC_BOOKING_API_URL`을 지정하면 예약·커뮤니티 요청은 그 주소를 우선 사용합니다.

```bash
cd app
npm ci
npm run dev
```

API는 API 브랜치의 `api/`에서 Python 가상환경과 서버 인증 설정을 준비한 뒤 실행합니다. 로컬 검토 시 자동반납과 실제 예약을 끈 상태로 시작할 수 있습니다.

```bash
cd api
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
BOOKING_ENABLED=false DAILY_RETURN_ENABLED=false AUTO_RETURN_ENABLED=false python3 -m uvicorn main:app --reload --port 8000
```

API 브랜치의 저장소 루트에서, 의존성을 설치한 Python 환경으로 테스트합니다.

```bash
python3 -m unittest discover -s api -p 'test_*.py'
```
